# Fragments Geometry — Developer Reference

How BIM graph nodes are converted into `@thatopen/fragments` tiles for OBC selection,
clipping, and attribute queries.

> **Scope:** `src/lib/fragModelBuilder.ts`, `src/lib/bimGeometryThree.ts`
> **Related:** `src/lib/bimGeometry.ts` (engine-agnostic math), `src/lib/emptyFragModel.b64.ts` (seed buffer)

---

## Architecture Overview

```
BIM graph nodes + edges
        │
        ▼
buildBimFragmentsModel()          ← fragModelBuilder.ts
        │
        ├─ Three.js geometry  ─────────── BoxGeometry / ExtrudeGeometry
        │                                 wallProfileMesh()  (bimGeometryThree.ts)
        │                                 ringGeo()
        │
        ├─ Boolean ops (CSG)  ─────────── applyOpeningVoids()  (three-bvh-csg)
        │
        ├─ NewElementData[]   ─────────── attributes + geometry + material
        │
        ▼
core.editor.createElements(modelId, elements)
        │
        ▼
FragmentsModel tiles  ──────────── OBF.Highlighter / OBC Clipper
```

The fragments model is **not** the primary renderer.  
Visual fidelity comes from the Three.js scene built by `buildSceneGeometry()` in
`WebIfcViewer.tsx`. The fragments model exists only for:

- Click-to-select (OBF.Highlighter raycasts tiles)
- Section fill colour (OBC ClipStyler on tiles)
- Metadata / attribute queries (`getItemsByQuery`)

---

## Coordinate System

```
BIM (mm)   →   Three.js (metres)
─────────────────────────────────
X (East)   →   +X
Y (North)  →   −Z  (negated — Three.js is right-handed, BIM is left-handed in plan)
Z (Up)     →   +Y
```

Conversion constant: `MM = 0.001` (millimetres → metres).

All geometry in the fragments model is in **Three.js world space** (metres, Y-up).
Geometry is baked into the `BufferGeometry` before it is passed to `createElements`,
so `globalTransform` for most shapes is the identity matrix.

The only shapes that use a non-identity `globalTransform` are simple
`BoxGeometry` primitives (columns, beams, slabs), where translation + rotation
are carried in the matrix rather than in the geometry.

## Seed Buffer

Fragments' `FragmentsModels.load()` requires an existing FlatBuffer binary as its
starting point — it cannot create a model from nothing.

`src/lib/emptyFragModel.b64.ts` contains a 1392-byte base64 string generated by
`scripts/gen_empty_frag.mjs`. It encodes a minimal IFC4 project
(`schema: "IFC4"`, one IfcProject, units, representation context) in raw
(uncompressed) fragments format.

```ts
const seedBytes = Uint8Array.from(atob(EMPTY_FRAG_MODEL_B64), c => c.charCodeAt(0));
await core.load(seedBytes, { modelId: BIM_MODEL_ID, raw: true });
```

`raw: true` tells the loader the buffer is already an uncompressed FlatBuffer.

## Model Lifecycle

```ts
export const BIM_MODEL_ID = 'bubblgraph-bim';

// 1. Dispose any previous model first
if (core.models.list.has(BIM_MODEL_ID)) {
  await core.disposeModel(BIM_MODEL_ID);
}

// 2. Load seed → bare model
await core.load(seedBytes, { modelId: BIM_MODEL_ID, raw: true });

// 3. Build NewElementData[]
const elements: NewElementData[] = [...];

// 4. Push tiles
await core.editor.createElements(BIM_MODEL_ID, elements);

// 5. Flush renderer (REQUIRED or tiles stay invisible)
await core.update(true);
```

**Guard `disposeModel`** — calling it on a model that doesn't exist throws.
Always check `core.models.list.has(id)` first.

**`await core.update(true)`** — must be called after `createElements` or the tiles
won't appear in the scene. The boolean `true` forces an immediate flush.

## `NewElementData` Structure

```ts
interface NewElementData {
  attributes:    Record<string, { value: string | number; type?: string }>;
  globalTransform: THREE.Matrix4;
  samples: Array<{
    localTransform:  THREE.Matrix4;
    representation: THREE.BufferGeometry;
    material:       THREE.Material;
  }>;
}
```

### Required Attributes

`@thatopen/fragments` v3.4.1 reads attributes through `itemDataToRawItemData`
which expects **underscore-prefixed** special keys:

| Key         | Required | Value example        | Notes                            |
|-------------|----------|----------------------|----------------------------------|
| `_category` | **YES**  | `'IFCWALL'`          | Missing → throws "Category is required" |
| `_guid`     | **YES**  | `node.id`            | Unique item identifier           |
| `Name`      | no       | `node.name`          | `type: 'IFCLABEL'`               |
| `BubbleId`  | no       | `node.id`            | Used by `getLocalIdByBubbleId()` |
| `BubbleType`| no       | `node.type`          | Used for category queries        |

All `node.properties` keys are also stored as `IFCLABEL` attributes so metadata
queries can filter by any BIM property.

## Geometry Validation

Before passing a `BufferGeometry` to `createElements`, two checks are applied.

### 1. `isValidGeo(geo)`

Returns `false` if:
- `position` attribute is missing or has 0 vertices
- any coordinate in the `position` array is non-finite (`Infinity`, `NaN`)

Elements that fail this check are silently dropped (`el()` returns `null`).

### 2. `prepareGeo(geo)`

`fragments` internal code does `index.array` directly (no null check).
`THREE.ExtrudeGeometry` and `THREE.ShapeGeometry` produce **non-indexed** geometry
(triangle soup, `getIndex() === null`) which causes a runtime crash.

`prepareGeo` adds a sequential `Uint32Array` index when none is present:

```ts
function prepareGeo(geo: THREE.BufferGeometry): THREE.BufferGeometry {
  geo.deleteAttribute('uv');      // not needed by fragments
  geo.deleteAttribute('uv1');
  if (geo.getIndex()) return geo; // already indexed
  const count = geo.getAttribute('position').count;
  const indices = new Uint32Array(count);
  for (let i = 0; i < count; i++) indices[i] = i;
  geo.setIndex(new THREE.BufferAttribute(indices, 1));
  return geo;
}
```

UV attributes are also removed to keep tile payloads small.

## Geometry Primitives

### Columns and Beams — `BoxGeometry`

Simple box: `new THREE.BoxGeometry(w, h, d)`.  
Position and rotation are carried in `globalTransform` via `poseMatrix(x, y, z, rotY)`.

```ts
// Column from ax node
const { w, d } = parseColumnDims(String(n.properties.column_type ?? 'C25x25'));
// C25x25 → w=0.25, d=0.25  (cm → metres, divide by 100 not 1000)
const h = (top - bot) * MM;
elements.push(el(n, 'IFCCOLUMN',
  new THREE.BoxGeometry(w, h, d), mat,
  poseMatrix(rx * MM, (bot + h_mm / 2) * MM, -ry * MM)));
```

Column/beam type strings use **centimetres**:
- `C25x25` → 0.25 × 0.25 m column
- `B30x60` → 0.30 m wide × 0.60 m deep beam

### Rooms and Slabs — `extrudedShape(poly, depthM)`

Builds a `THREE.ExtrudeGeometry` from a BIM polygon (units: mm), then rotates
`-π/2` around X so the extrusion goes along +Y (up) instead of +Z.

```ts
function extrudedShape(poly: {x:number; y:number}[], depthM: number): THREE.BufferGeometry {
  const shape = new THREE.Shape();
  shape.moveTo(poly[0].x * MM, poly[0].y * MM);
  for (let i = 1; i < poly.length; i++) shape.lineTo(poly[i].x * MM, poly[i].y * MM);
  shape.closePath();
  const geo = new THREE.ExtrudeGeometry(shape, { depth: depthM, bevelEnabled: false });
  geo.rotateX(-Math.PI / 2); // ExtrudeGeometry extrudes along +Z; rotate to +Y
  return geo;
}
```

After constructing, call `geo.translate(0, bot * MM, 0)` to place the base at the
storey bottom elevation. The geometry is then in world space and `globalTransform`
is the identity matrix.

### Shell and Covering — `ringGeo(outer, inner, heightM)`

A hollow vertical extrusion (ring cross-section).

```
outer polygon  ──────────┐  ← outside face
inner polygon  ──┐       │  ← inside face (hole in Shape)
                 └───────┘
```

Implementation:

```ts
function ringGeo(outer, inner, heightM): THREE.BufferGeometry | null {
  const shape = new THREE.Shape();
  // outer path
  shape.moveTo(outer[0].x * MM, outer[0].y * MM);
  for (const p of outer.slice(1)) shape.lineTo(p.x * MM, p.y * MM);
  shape.closePath();
  // inner path as a hole (reversed winding)
  const hole = new THREE.Path();
  const rev = [...inner].reverse();
  hole.moveTo(rev[0].x * MM, rev[0].y * MM);
  for (const p of rev.slice(1)) hole.lineTo(p.x * MM, p.y * MM);
  hole.closePath();
  shape.holes.push(hole);
  // extrude up
  const geo = new THREE.ExtrudeGeometry(shape, { depth: heightM, bevelEnabled: false });
  geo.rotateX(-Math.PI / 2);
  return geo;
}
```

The inner polygon is computed by `insetPolygon(outer, inward.map(v => v + thickMm))`
where `thickMm` is the wall thickness (default 200 mm).

## Wall Geometry — `wallProfileMesh()`

Walls use `THREE.ExtrudeGeometry` with **2-D Shape holes** to represent openings,
rather than decomposing into multiple box segments.

This produces a single clean mesh whose only silhouette edges are the outer wall
perimeter and the opening frames — eliminating internal face-edge artefacts in
elevation drawings.

### Shape Convention (wall-local space)

```
X = distance along wall     0 → wallLen  (metres)
Y = vertical elevation      0 → wallH    (metres from wall bottom)
Z = through-wall depth      0 → wallThick (extruded)
```

### Opening Holes

Each `OpeningMeshDesc` from `calcWallGeometry()` contributes one rectangular hole:

```ts
const hole = new THREE.Path();
hole.moveTo(op.tS,          op.sill);           // left, bottom
hole.lineTo(op.tS + op.oW, op.sill);           // right, bottom
hole.lineTo(op.tS + op.oW, op.sill + op.oH);  // right, top
hole.lineTo(op.tS,          op.sill + op.oH);  // left, top
hole.closePath();
shape.holes.push(hole);
```

`op.tS` = tangential start (left edge of opening along wall, metres)  
`op.oW` = opening width (metres)  
`op.oH` = opening height (metres)  
`op.sill` = sill height from wall bottom (metres)

### World-Space Basis Transform

After extrusion the geometry is rotated from wall-local to Three.js world space
by applying a 4×4 basis matrix:

```
wall along-vector  → Three.js along-direction in XZ
up (+Y local)      → Three.js +Y
wall normal        → Three.js perpendicular in XZ, centred on centre-line
```

```ts
extGeo.applyMatrix4(new THREE.Matrix4().set(
  wux,  0, wnx,  ox,    // row 0: X col = along direction
    0,  1,   0, botM,   // row 1: Y col = up, shift to botM
  wuz,  0, wnz,  oz,    // row 2: Z col = normal direction
    0,  0,   0,  1,
));
extGeo.computeVertexNormals();
```

After this transform the geometry is in world space; `globalTransform = identity`.

## Boolean Operations (CSG)

Uses `three-bvh-csg` (`Evaluator`, `Brush`, `SUBTRACTION`).

### `makeBoxOpeningCutter(op: OpeningMeshDesc): Brush`

Creates a `BoxGeometry` brush sized and positioned to cut one opening void
through any solid that occupies the same space:

```ts
export function makeBoxOpeningCutter(op: OpeningMeshDesc): Brush {
  const cutDepthM = op.node?.properties.cut_depth
    ? Math.max(0.05, Number(op.node.properties.cut_depth) * MM)
    : 1.0;  // default 1 m — cuts through any reasonable wall
  const b = new Brush(new THREE.BoxGeometry(op.oW, op.oH, cutDepthM));
  b.position.set(op.cx, op.botY + op.sill + op.oH / 2, op.cz);
  b.rotation.y = Math.atan2(op.uz, op.ux); // align to wall direction
  b.updateMatrixWorld();
  return b;
}
```

`op.cx / op.cz` = world-space centre of the opening (on the wall centre-line).

### `applyOpeningVoids(wallMesh, cutters): THREE.Mesh`

Subtracts every cutter brush from the wall (or ring) mesh using a CSG Evaluator.

Key behaviour:
- The input mesh's own `matrix` (position/rotation) is **baked** into the geometry
  clone before CSG. Ring meshes carry `position.y = botM` — this bake folds it in.
- On **any** CSG failure, the original solid mesh is returned so rendering never breaks.
- A singleton `Evaluator` is reused across calls to avoid repeated WASM init.

```ts
wallMesh.updateMatrix();
const geoForCsg = wallMesh.geometry.clone().applyMatrix4(wallMesh.matrix);
let brushA = new Brush(geoForCsg, wallMesh.material);
brushA.updateMatrixWorld();
for (const cutter of cutters) {
  const target = new Brush();
  evaluator.evaluate(brushA, cutter, SUBTRACTION, target);
  brushA = target;
  brushA.updateMatrixWorld();
}
return new THREE.Mesh(brushA.geometry, wallMesh.material);
```

### When CSG is Applied

| Element | CSG used | Why |
|---------|----------|-----|
| `wall`  | optional — only if Shape holes are not enough | 2-D holes handle most cases; CSG added for correctness on complex walls |
| `shell` | yes — `allCutters` from all walls | Ring extrusion cannot express side holes as Shape holes (no per-face decomposition) |
| `covering` (node) | yes — `allCutters` | Same reason as shell |
| `covering` (room-derived) | yes — `allCutters` | Same reason |

`allCutters` is built once per `buildBimFragmentsModel` call by iterating over
all `wall` nodes and collecting their `OpeningMeshDesc[]`:

```ts
const allCutters: ReturnType<typeof makeBoxOpeningCutter>[] = [];
for (const wn of nodes.filter(n => n.type === 'wall')) {
  const geo = calcWallGeometry(wn, nodeMap, edges);
  if (!geo) continue;
  for (const op of geo.openings) allCutters.push(makeBoxOpeningCutter(op));
}
```

## Slab Sources

There are two independent slab generation paths:

### 1. Standalone `slab` nodes

Footprint derived from the bounding box of all sibling nodes in the same storey.
Placed at `top * MM - th / 2` (top of storey band minus half slab thickness).

```
sw = max(sibling.x) − min(sibling.x) + 2 * contourOffset
sd = max(sibling.y) − min(sibling.y) + 2 * contourOffset
```

Uses `BoxGeometry(sw, th, sd)` with a translation matrix.

### 2. Room-derived slabs (`has_slab` on room nodes)

When a room node has `has_slab !== false`, a synthetic slab element is generated
at the **top** of the room volume using the room polygon:

```ts
const slabGeo = extrudedShape(poly, slabTh);
slabGeo.translate(0, (bot + roomH) * MM, 0);
```

The synthetic slab gets `id = roomId + '-slab'` so it appears as a distinct item
in the fragments model but shares the room's storey band.

Slab thickness is parsed from the `slab_type` property (e.g. `SLAB15` → 0.15 m).

---

## Covering Sources

Coverings also have two generation paths:

### 1. Standalone `covering` nodes

Ring extrusion from `calcShellPolygon()` (connected ax/column nodes, sorted radially).  
Same pipeline as shell, CSG applied from `allCutters`.

### 2. Room-derived coverings (`has_covering` on room nodes)

When a room node has `has_covering !== false`, a ring mesh is derived from the
room polygon using `covering_thickness` (default 150 mm):

```ts
const outer = insetPolygon(poly, inward);
const inner = insetPolygon(poly, inward.map(v => v + thickMm));
const geo   = ringGeo(outer, inner, covH);
geo.translate(0, bot * MM, 0);
// then applyOpeningVoids(mesh, allCutters)
```

The synthetic covering gets `id = roomId + '-cov'`.

## Querying the Model

### By BubbleId → localId

Used to map a selected node in the graph editor to a fragments item for highlighting:

```ts
export async function getLocalIdByBubbleId(
  core: FragmentsModels,
  bubbleId: string,
): Promise<number | null> {
  const model = core.models.list.get(BIM_MODEL_ID);
  if (!model) return null;
  const results = await model.getItemsByQuery({
    attributes: { queries: [{ name: /^BubbleId$/, value: new RegExp(`^${bubbleId}$`) }] },
  });
  return results[0] ?? null;
}
```

### By localId → BubbleId

Used by OBF.Highlighter's `onHighlight` event to map a fragments hit back to a
node ID in the Zustand store:

```ts
export async function getBubbleIdByLocalId(
  core: FragmentsModels,
  localId: number,
): Promise<string | null> { ... }
```

### Highlighter Setup

```ts
const highlighter = components.get(OBF.Highlighter);
highlighter.setup({ world });
highlighter.styles.set('select', {
  meshes: new Set(),
  rendererMaterial: new THREE.MeshBasicMaterial({ color: 0xff8800, depthTest: false }),
});

// Highlight by localId
const lid = await getLocalIdByBubbleId(core, nodeId);
if (lid !== null) {
  await highlighter.highlightByID('select', { [BIM_MODEL_ID]: new Set([lid]) });
}
```

`highlightByID` expects `ModelIdMap = Record<string, Set<number>>` — **Set, not array**.

## Known Limitations

| Issue | Status |
|-------|--------|
| Shell/covering side holes can't use Shape holes | By design — ring extrusions use 3-D CSG instead |
| Slab footprint for standalone nodes is a bounding box, not a true polygon | Acceptable for OBC queries; 3D visual uses WebIfcViewer polygon |
| Room volume is semi-transparent (opacity 0.12) but still raycasted by Highlighter | May cause false clicks through room; mitigate by ray-casting only element tiles |
| `ExtrudeGeometry` is non-indexed (`getIndex() === null`) | Fixed by `prepareGeo()` — adds sequential Uint32 index |
